# Cursor SDK 供应商

`dsh-cursor-provider` 为 DeepSeek Harness（DSH）接入 Cursor 官方 SDK，注册 `cursor` 模型供应商。当前版本为 **0.2.3**，使用 `@cursor/sdk` 1.0.40，采用 [MIT 许可](LICENSE)。

**这是 Cursor SDK agent 接入，不是普通的原始模型 API 接入。** 请求经过 Cursor 的 agent 运行时和服务端，仍受其内建系统提示词及账号权限约束，不能视为“纯净 Grok”或其他模型的直连 API。通过「获取可用模型」勾选并确认添加新模型时，插件会在名称前自动填入 `Cursor `（例如 `Cursor Grok 4.7`），模型 ID 不变；已有模型名称和之后手动修改的名称保留，已有 Cursor 前缀不会重复添加。

DSH 的 system 和历史会作为对话数据交给 SDK，不能等同于替换 Cursor 系统提示词。工具通过结构化桥接交回 DSH 审批与执行，SDK 内建工具保持关闭。

## 安装与配置

需要 Node.js **24.9 或更新版本**。DSH 最低版本要求为 `>=0.2.1-rc.3`，不设上限。已在 rc.3 和 rc.5 的接口与回归测试中验证；允许新版本加载不代表新版本均已通过验收。

1. 在 DSH 插件管理器中安装 npm 包 `dsh-cursor-provider`。
2. 打开「插件 → Cursor → 详情」，填写并保存 Cursor API 密钥。
3. 点击「获取可用模型」，搜索并勾选账号可用的模型，保存配置。
4. 在聊天输入栏选择 Cursor 模型后开始会话。

密钥通过 DSH 凭据服务保存，输入框不会回填已存密钥。密钥和模型配置分别保存；若配置保存失败，可以留空密钥栏后重试。

模型列表只显示基础模型，不展示 `@context=…` 等参数组合。模型行可设置 ID、显示名称、文字或图片输入类型，以及上下文预算；输入类型至少保留一种。保存空模型列表会隐藏所有 Cursor 模型。

上下文窗口保留手动填写，支持 `500K`、`1M` 等写法，有效输入在失去焦点后转成大写。模型目录声明 `context` 档位时，插件把手填值交给 DSH 作为预算，并为 Cursor SDK 选择不小于预算的最小档位。例如档位为 250K、500K 时，350K 对应 SDK 500K，150K 或 149K 对应 SDK 250K；DSH 仍按手填值计算预算，压缩时机由宿主决定。未填写时，SDK 和 DSH 使用目录声明的最大档位。超过最大档位或格式错误时会显示模型序号并禁用保存。

新增模型只初始化一次最大已声明窗口，已有数值和空值不会自动回填。模型未声明 `context` 时，手填值只影响 DSH，不改变 SDK 参数；留空显示“使用提供商默认值”，容量保持未知。

只有账号目录声明可开关 Fast 的模型才显示 Fast 选项，默认关闭。启用后，插件在名称未含 Fast 时自动追加 ` Fast`；关闭时只移除自动追加的后缀，保留用户自定义名称。面板的 Fast 能力结果在内存缓存 24 小时，手动获取立即刷新。成功刷新确认能力消失时，会关闭已保存的 Fast 并移除自动后缀；查询失败不改动设置。Fast 可能消耗更多用量。

模型目录按账号在内存缓存 5 分钟，最多保留 8 个账号。「获取可用模型」会强制刷新；更换密钥后不会复用其他账号的目录。

## 工具与图片

插件通过 SDK `local.customTools` 注册 DSH 工具的原名、描述和 JSON Schema。SDK 回调交付结构化调用，**审批和执行仍由 DSH 负责**；插件把工具结果、拒绝状态及图片结果回传 SDK。模型正文不会被当成工具指令解析。

一次工具循环复用同一个隔离 SDK agent/run，支持工具交接期间追加或替换带宿主来源的 runtime-context 快照。审批等待计入默认 30 分钟的 run 超时；待回传工具结果的续接只保存在当前进程内，重启、卸载或超时后不能恢复。插件不会因回答未调用工具而自动追加纠正请求。

图片由 DSH 附件服务读取，再通过 SDK 图片附件发送；已 offload 的图片保留文字占位。模型行的图片选项控制 DSH 是否传递图片，不代表该模型一定支持视觉。真实单图发送已验证，多图及工具返回图片的真实识别仍待验收。

## 跨轮复用、压缩与缓存

同一 DSH 会话的历史严格追加，且账号、模型参数、工具、system 和工具历史配置一致时，插件复用 SDK agent，只发送新增用户消息。历史压缩、旧快照替换、其他历史改写或身份配置变化会触发重建，并重新发送当前历史。图片路径暂时保守重建；会话标题、压缩等辅助请求不进入跨轮缓存。并发请求不会共享正在执行的 agent。

空闲 agent 最多保留 8 个，默认 30 分钟后释放；进程重启或插件卸载也会释放，不跨进程恢复。回收后，普通会话的下一次请求会从 DSH 当前历史重建，无需仅因空闲缓存到期而新建 DSH 会话。

**SDK 对话状态不等于模型端前缀缓存。** [Cursor SDK 文档](https://cursor.com/docs/sdk/typescript.md#conversation-context)说明 `Agent.create()` 创建新的对话状态，后续 `send()` 才沿用该 agent 的 checkpoint；所查官方文档没有保证缓存是否按 agent 隔离或能否跨 agent 复用。因此，重建后的缓存命中率与费用可能变化，不能说必然全部失效；复用 agent 同样不保证命中。压缩会改写历史，被改写部分不能继续按原来的相同前缀处理。

只发送新增消息不代表上游只处理新增 token。SDK 仍携带对话上下文，缓存命中也不扩大模型窗口。请保留 DSH 的上下文预算与压缩兜底，不要因复用 agent 而无限追加。

## 使用限制

- 不支持自定义 API 地址。模型目录来自当前账号，未知的价格、视觉能力和上下文容量不会用其他平台的数据补齐。
- SDK 未提供插件所需的 temperature、maxTokens、stop 等控制；无法表达的参数会在推理前拒绝。最大输出 token 配置不可编辑。
- SDK 的内建文件、终端工具及环境设置导入关闭，仅启用自定义工具所需的 MCP 通道，不配置外部 MCP 服务。agent 的工作目录和 JSONL store 位于临时目录，未缓存的请求完成、空闲回收、取消、卸载或超时后清理。临时目录不是操作系统安全沙箱。
- SDK 自动重试已关闭。宿主会话日志仍包含模型内容和工具调用，插件不额外记录原始 SDK 事件或凭据。
- SDK 1.0.40 没有已确认的公开上游标头注入入口，本插件不发送 DSH attribution headers；这不代表 DSH 官方认证。实现仅调用 SDK 公开接口。

当前安装依赖的审计报告中，宿主 peer `@deepseek-ai/dsh-llm` 的嵌套 zod 命中高危公告 **GHSA-mrhx-c7xc-m3w5**。本插件没有强制覆盖宿主依赖，风险需由兼容的宿主依赖升级解决。

## 系统提示词替换实验（未发布）

完整替换实验默认关闭，普通插件调用不传 SDK `systemPrompt`。仅显式创建 `CursorTransport({ replaceSystemPrompt: true })` 时，非空 DSH `system` 才原样传入该参数，不再放进用户消息 JSON；实验模式的空 system 使用 `You are an AI assistant.`。实验失败不会自动切回普通模式。

2026-10-30 使用临时凭据对 Grok 4.7 做了两次请求尝试。SDK 返回的错误同时包含系统提示词参数、`InvalidArgument` 和权限拒绝；请求未进入 DSH 工具交接阶段。当前账号尚不能使用这个服务端受限接口，插件不会退回 Cursor 默认提示词。0.2.3 仅更新来源标识与接入说明，不把完整替换实验作为默认功能，也不声称已经获得“纯净 Grok”。

手动验收入口为 `node scripts/check-system-prompt.mjs`，需要在测试进程中设置 `CURSOR_API_KEY`，会产生真实模型请求。脚本检查系统指令相对用户指令的优先级、结构化工具调用和 DSH 结果回传，不读取旧会话中的凭据。只有真实验收通过后才考虑升到 0.3.0。

## 开发与检查

```sh
npm ci
npm run check
npm run pack:check
```

`check` 运行测试并构建；`pack:check` 检查发布包。测试覆盖真实 DSH 流记录器、连续工具续接、快照追加与替换、结果匹配、拒绝、取消、超时、目录缓存及图片传递等路径。自动测试使用 mock，不读取既有密钥。原生工具请求、结果回传和新快照读取曾通过真实 Grok 4.7 验证；0.2.0 新增的跨用户轮次复用通过离线测试，尚未完成真实上游调用验收，也不承诺缓存命中率。

发布包包含运行源码、bundle patch、locale、图标、设计参考、README 和 LICENSE；不包含测试、临时脚本或私有配置备份。配置界面的离线参考见 [design/cursor-provider.html](design/cursor-provider.html)，该文件不连接后端。
